## 1. Purpose

Receipt Adapter는 외부 Provider 또는 내부 실행계층에서 전달된 receipt-like input을 **기존 Receipt/Provenance/Evidence 체계를 변경하지 않고** canonical receipt envelope로 정규화·검증하는 경계 모듈이다.

Receipt Adapter의 역할은 **형식·무결성·재현성 검증**까지이다. Receipt Adapter는 trust를 부여하거나 dispatch를 승인하지 않는다.

핵심 원칙:

1. Provider input은 기본적으로 untrusted이다.
2. 기존 Receipt, Provenance, Evidence Ledger, Trusted Merge는 변경하지 않는다.
3. 동일 입력은 동일 canonical output 또는 동일 rejection을 생성해야 한다.
4. Adapter는 권한을 생성·확대·추론하지 않는다.
5. 검증 실패·모호성·알 수 없는 schema는 fail-closed 처리한다.

## 3. Requirements

### RA-001 — Preserve Existing Trust Assets

Receipt Adapter 구현을 위해 기존 Receipt, Provenance, Immutable Evidence, Evidence Ledger, Trusted Merge 의미론을 변경해서는 안 된다.

### RA-002 — Deterministic Canonicalization

동일 byte-equivalent 또는 contract상 동등한 source input은 동일 canonical serialization과 동일 `payloadDigest`를 생성해야 한다.

### RA-003 — No Silent Mutation

Source 값이 수정·보정·추론되는 경우 원본 값과 변환 규칙이 모두 audit metadata에 남아야 한다. 의미를 바꾸는 silent coercion은 금지한다.

### RA-004 — Fail Closed

다음은 모두 reject한다.

- 알 수 없는 schema version
- 필수 필드 누락
- 모호한 encoding
- digest 불일치
- 지원되지 않는 receipt type
- 식별 불가능한 provider
- 허용범위를 벗어난 timestamp
- canonicalization 충돌

### RA-005 — Idempotency

동일 source receipt의 반복 입력은 새로운 logical receipt를 생성하지 않아야 한다.

### RA-006 — Replay Signal

Adapter는 replay/duplicate 판정을 위한 stable identity를 산출해야 한다. 최종 replay policy는 상위 control layer가 결정한다.

### RA-007 — No Trust Escalation

Adapter output은 `trusted=true`, `authorized=true` 같은 상위 결정을 직접 부여할 수 없다.

### RA-008 — Immutable Source Reference

가능한 경우 원본 payload 자체가 아니라 immutable source reference 또는 digest를 보존한다. 원본 저장정책은 기존 evidence policy를 따른다.

### RA-009 — Bounded Input

Payload size, nesting depth, field count, string length 등 resource limits를 적용해 parser/resource exhaustion을 차단한다.

### RA-010 — Versioned Contract

Canonical receipt schema는 `schemaVersion`을 반드시 포함한다. Breaking change는 새 schema version으로만 허용한다.

권고 구현 위치:

```text
src/trust/receipt-adapter/

  canonicalize.ts
  validators.ts
```

Public interface:

```typescript
export interface ReceiptAdapter {
  adapt(request: ReceiptAdapterRequest): ReceiptAdapterResult
}

export interface ReceiptAdapterRequest {
  providerId: string
  receiptType: string
  sourceSchemaVersion: string
  sourceReceiptId?: string
  rawPayload: unknown
  observedAt: string
  traceId: string
  authorityRef?: string
  evidenceRefs?: readonly string[]
}

type ReceiptAdapterResult =
  | { ok: true; receipt: CanonicalReceiptEnvelope; audit: ReceiptAdapterAudit }
  | { ok: false; error: ReceiptAdapterError; audit: ReceiptAdapterAudit }
```

Receipt Adapter는 synchronous pure-core 형태를 기본으로 한다. I/O가 필요한 provider-specific decoding은 별도 boundary에서 수행하고, core adapter에는 이미 수신된 input만 전달한다.

## 5. Data Model

```typescript
export interface CanonicalReceiptEnvelope {
  schemaVersion: "1"
  receiptId: string
  providerId: string
  providerReceiptId?: string
  receiptType: string
  subjectId?: string

  replayKey: string
}

export interface ReceiptAdapterAudit {
  traceId: string
  providerId: string
  sourceSchemaVersion: string
  targetSchemaVersion: "1"
  inputDigest: string
  outputDigest?: string
  transformations: readonly string[]
  decision: "EMITTED" | "REJECTED"
  reasonCode?: ReceiptAdapterErrorCode
}
```

### Canonical Identity

`receiptId`는 random UUID만으로 결정하지 않는다. 동일 source receipt에 대해 재현 가능한 identity가 필요하다.

권고:

```text
receiptId = stableHash(providerId + receiptType + providerReceiptId/source identity + payloadDigest)
```

실제 hash algorithm은 기존 platform crypto standard를 재사용한다. 새로운 crypto primitive를 이 문서에서 도입하지 않는다.

### Time Representation

모든 contract timestamp는 timezone을 포함한 RFC 3339/ISO-8601 canonical UTC representation을 사용한다.

## 6. State Machine

```text
RECEIVED
  ↓ parse
PARSED
  ↓ identify schema/provider/type
IDENTIFIED
  ↓ canonicalize
NORMALIZED
  ↓ validate required fields / time / digest / limits
VALIDATED
  ↓ emit
EMITTED
```

Terminal failure:

```text
RECEIVED | PARSED | IDENTIFIED | NORMALIZED | VALIDATED
  └──> REJECTED
```

규칙:

- `EMITTED`와 `REJECTED`는 terminal이다.
- 동일 입력 재처리는 동일 terminal result를 반환해야 한다.
- terminal result를 후속 호출로 mutable state처럼 변경하지 않는다.

## 7. Error Model

```typescript
export type ReceiptAdapterErrorCode =
  | "RA-001_MALFORMED_INPUT"
  | "RA-002_UNSUPPORTED_SCHEMA"
  | "RA-003_UNKNOWN_PROVIDER"
  | "RA-004_UNSUPPORTED_RECEIPT_TYPE"
  | "RA-005_REQUIRED_FIELD_MISSING"
  | "RA-006_INVALID_TIMESTAMP"
  | "RA-007_DIGEST_MISMATCH"
  | "RA-008_CANONICALIZATION_CONFLICT"
  | "RA-009_DUPLICATE_OR_REPLAY"
  | "RA-010_RESOURCE_LIMIT_EXCEEDED"
  | "RA-011_AMBIGUOUS_ENCODING"
  | "RA-012_INTERNAL_ADAPTER_ERROR"
```

Error response는 다음을 보장한다.

- machine-readable code
- human-readable message
- `traceId`
- reject 단계
- 안전한 diagnostics

Raw secret, credential, full provider payload는 error/log에 기록하지 않는다.

`RA-009_DUPLICATE_OR_REPLAY`는 policy에 따라 idempotent success로 흡수될 수 있다. 단, 동일 replay key가 서로 다른 payload digest를 가리키면 반드시 conflict/reject이다.

## 8. Security Requirements

1. 모든 provider-controlled input을 untrusted로 취급한다.
2. parser는 prototype pollution, oversized payload, deep nesting, malformed encoding을 방어한다.
3. canonical serializer는 key order/number/string encoding에 대해 deterministic 해야 한다.
4. digest 비교는 기존 platform security utility를 사용한다.
5. secret/token/API key를 canonical payload나 audit log에 복제하지 않는다.
6. authority reference는 opaque reference로 취급하며 Adapter가 권한 유효성을 자체 판단하지 않는다.
7. source receipt에 포함된 trust/role/permission 표시는 상위 authority로 승격하지 않는다.
8. 기존 provenance/evidence reference를 삭제·대체하지 않는다.
9. unknown version은 permissive parse하지 않고 reject한다.
10. 모든 rejection은 audit 가능한 reason code를 남긴다.

## 9. Acceptance Tests

### AT-002-001 — Valid Receipt

Given 지원 provider의 valid receipt
When `adapt()`
Then `ok=true`, canonical envelope 1개, audit `EMITTED`.

### AT-002-002 — Determinism

동일 input을 100회 처리했을 때 canonical serialization, `receiptId`, `payloadDigest`, `replayKey`가 모두 동일해야 한다.

### AT-002-003 — Idempotent Duplicate

동일 logical receipt가 재입력되어도 서로 다른 logical receipt가 생성되지 않아야 한다.

### AT-002-004 — Digest Mismatch

Declared/known digest와 payload digest가 다르면 `RA-007_DIGEST_MISMATCH`로 reject.

### AT-002-005 — Unknown Schema

지원하지 않는 source schema는 `RA-002_UNSUPPORTED_SCHEMA`로 reject.

### AT-002-006 — Missing Required Field

필수 식별정보가 없으면 `RA-005_REQUIRED_FIELD_MISSING`으로 reject.

### AT-002-007 — Invalid Timestamp

형식 오류 또는 policy 범위를 벗어난 timestamp는 reject.

### AT-002-008 — Unknown Provider

등록되지 않은 provider는 reject. Core가 임의 provider를 자동등록하지 않는다.

### AT-002-009 — Resource Limits

size/depth/field-count 제한 초과 input은 안전하게 reject하고 process crash가 없어야 한다.

### AT-002-010 — No Trust Decision

Receipt Adapter output/API에 trust grant 또는 dispatch allow를 생성하는 code path가 없어야 한다.

### AT-002-011 — Canonical Collision

동일 replay identity에 상이한 payload digest가 나타나면 silent overwrite 없이 reject한다.

### AT-002-012 — Existing Core Regression

기존 Receipt/Provenance/Evidence/Trusted Merge regression suite가 모두 PASS해야 한다.
