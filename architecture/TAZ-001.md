## 1. Purpose

Trust Controller는 TAZ의 **최소 orchestration/state-decision module**이다. Receipt Adapter(TAZ-002)의 검증 결과와 Authority Contract(TAZ-003)의 authorization 결과를 결합해, 특정 task/session이 dispatch 가능한지 여부를 결정한다.

Trust Controller는 trust evidence를 직접 만들지 않고, authority를 발급하지 않으며, provider를 호출하지 않는다. 기존 Receipt/Provenance/Evidence 체계와 하위 adapter의 결과를 참조해 명시적 state transition만 관리한다.

핵심 원칙:

1. Receipt verification과 Authority authorization을 분리한다.
2. 둘 중 필수 조건 하나라도 충족되지 않으면 dispatch-ready가 아니다.
3. Trust Controller는 provider/runtime/repository/business logic에 직접 의존하지 않는다.
4. 동일 immutable inputs에 대해 동일 decision을 생성한다.
5. unknown state 또는 dependency failure는 fail closed 한다.

## 2. Scope

### In Scope

- trust session 생성/종료
- receipt evaluation result 수용
- authority decision 수용
- trust state transition
- dispatch readiness decision
- explicit HOLD/BLOCKED/FAILED handling
- decision reason/audit record 생성
- trace/session/task correlation
- idempotent repeated evaluation

### Out of Scope

- Receipt parsing/canonicalization
- Authority issuance/revocation
- Provider 호출
- Dispatch 실행
- Repository write
- Evidence Ledger mutation
- Provenance mutation
- Business logic
- Portal logic
- Runtime execution
- Production/Public/G5 승인 자체

## 3. Requirements

### TC-001 — Explicit Inputs

Trust Controller는 receipt 결과와 authority 결과를 typed contract로만 받는다. Provider-native payload 또는 raw authority payload를 직접 해석하지 않는다.

### TC-002 — Receipt/Authority Separation

`receiptVerified=true`는 authorization을 의미하지 않으며, `authority=ALLOW`는 receipt/evidence requirement 충족을 의미하지 않는다.

### TC-003 — Fail Closed

필수 input 누락, unknown version, invalid state, dependency error, inconsistent reference는 `READY_FOR_DISPATCH`로 전이하지 않는다.

### TC-004 — Deterministic Decision

동일 session snapshot과 동일 receipt/authority results는 동일 trust state와 reason code를 생성해야 한다.

### TC-005 — Idempotent Evaluation

동일 evaluation input을 반복 제출해도 state가 중복 전이되거나 duplicate dispatch eligibility가 생성되지 않는다.

### TC-006 — Immutable Decision Inputs

각 decision은 사용한 receipt reference, authority reference/version, task/session/trace identifier를 audit record에 bind한다.

### TC-007 — Explicit Hold

Program Owner 또는 governance layer의 explicit HOLD가 존재하면 lower-level verified/authorized 상태보다 우선한다.

### TC-008 — No Provider Dependency

Trust Controller core는 provider SDK/API/client를 import하거나 직접 호출하지 않는다.

### TC-009 — No Repository Mutation

Trust Controller는 GitHub/Repository state를 변경하지 않는다. 영속화가 필요하면 외부 persistence boundary를 사용한다.

### TC-010 — Terminal Evidence Distinction

`DISPATCHED`는 success가 아니다. 완료는 terminal receipt/evidence가 확인된 뒤 `FINISHED`로 전이해야 한다.

### TC-011 — Bounded State Machine

정의되지 않은 state/transition은 허용하지 않으며 `TC-005_INVALID_TRANSITION`로 block한다.

### TC-012 — Protected Gate Preservation

Internal dispatch readiness는 Production/Public/G5 또는 owner-only approval을 자동 승인하지 않는다.

## 5. Data Model

```typescript
export type TrustState =
  | "SESSION_CREATED"
  | "RECEIPT_PENDING"
  | "AUTHORITY_PENDING"
  | "READY_FOR_DISPATCH"
  | "DISPATCHED"
  | "FINISHED"
  | "HOLD"
  | "BLOCKED"
  | "FAILED"

export interface TrustSessionSnapshot {
  schemaVersion: "2"
  sessionId: string
  taskId: string
  actorId: string
  traceId: string
  state: TrustState
  receipt?: ReceiptVerificationRef
  authority?: AuthorityDecisionRef
  protectedGateState: "CLEAR" | "HOLD" | "REQUIRED"
  createdAt: string
  updatedAt: string
  decisionVersion: number
  terminalEvidenceRefs: readonly string[]
  lastReasonCode?: TrustControllerReasonCode
}

export interface DispatchReadinessDecision {
  decision: "READY" | "NOT_READY"
  sessionId: string
  taskId: string
  traceId: string
  state: TrustState
  reasonCode?: TrustControllerReasonCode
  receiptRef?: string
  authorityRef?: string
  decisionVersion: number
}
```

Data rules:

- `sessionId`는 session 내에서 immutable.
- `taskId`와 `traceId`는 session 생성 이후 교체하지 않는다.
- `decisionVersion`은 successful state mutation마다 단조 증가한다.
- receipt/authority reference가 바뀌면 새 evaluation으로 취급한다.
- secret/token/raw provider payload를 session snapshot에 저장하지 않는다.

## 6. State Machine

정상 흐름:

```text
SESSION_CREATED
  ↓ receipt required
RECEIPT_PENDING
  ↓ receipt verified
AUTHORITY_PENDING
  ↓ authority ALLOW + protected gate clear
READY_FOR_DISPATCH
  ↓ external dispatch accepted
DISPATCHED
  ↓ terminal receipt/evidence confirmed
FINISHED
```

대체 순서가 필요한 경우 receipt와 authority result는 독립적으로 들어올 수 있다. 단, `READY_FOR_DISPATCH` 조건은 둘 다 충족된 뒤에만 성립한다.

Blocking branches:

```text
receipt invalid                → BLOCKED
authority DENY                 → BLOCKED
protected gate HOLD            → HOLD
invalid/inconsistent transition→ BLOCKED
unexpected internal failure    → FAILED
```

Transition rules:

1. `FINISHED`는 terminal이다.
2. `BLOCKED`, `FAILED`, `HOLD`에서 자동으로 READY로 복귀하지 않는다.
3. 복구는 명시적 new evaluation/session transition contract를 통해서만 허용한다.
4. `DISPATCHED` 이후 authority/receipt를 사후 교체해 과거 dispatch를 정당화하지 않는다.
5. terminal evidence 없이 `DISPATCHED → FINISHED` 전이 금지.
6. `protectedGateState != CLEAR`이면 READY 금지.

## 7. Error Model

```typescript
export type TrustControllerReasonCode =
  | "TC-001_INVALID_SESSION"
  | "TC-002_RECEIPT_REQUIRED"
  | "TC-003_RECEIPT_REJECTED"
  | "TC-004_AUTHORITY_DENIED"
  | "TC-005_INVALID_TRANSITION"
  | "TC-006_REFERENCE_MISMATCH"
  | "TC-007_PROTECTED_GATE_HOLD"
  | "TC-008_TERMINAL_EVIDENCE_REQUIRED"
  | "TC-009_UNSUPPORTED_VERSION"
  | "TC-010_DEPENDENCY_ERROR"
  | "TC-011_ALREADY_TERMINAL"
  | "TC-012_INTERNAL_ERROR"
```

Error rules:

- exception은 READY로 fallback하지 않는다.
- malformed input은 typed error/NOT_READY로 귀결한다.
- reason code와 `traceId`를 남긴다.
- raw credentials/sensitive provider body는 error에 포함하지 않는다.
- 동일 invalid transition을 반복해도 state를 추가 변형하지 않는다.

## 8. Security Requirements

1. receipt verification result를 source authority로 사용하지 않는다.
2. authority ALLOW만으로 missing receipt/evidence를 우회하지 않는다.
3. protected owner gate는 lower-level state보다 우선한다.
4. raw external input을 Controller에서 parse하지 않는다.
5. session/task/trace reference mismatch는 block한다.
6. stale authority/receipt reference를 새 decision에 혼용하지 않는다.
7. duplicate/replayed apply operation은 idempotent하게 처리한다.
8. unknown state/version은 fail closed.
9. logs에는 secret/token/full provider payload를 기록하지 않는다.
10. provider SDK, runtime executor, portal/business module을 core dependency로 추가하지 않는다.
11. terminal evidence reference는 immutable reference로만 연결한다.
12. state mutation은 audit 가능한 decisionVersion과 reason을 남긴다.

## 9. Acceptance Tests

### AT-001-001 — Session Creation

Valid create request → `SESSION_CREATED`, stable session/task/trace IDs.

### AT-001-002 — Valid Receipt Only

Receipt verified, authority 없음 → `READY_FOR_DISPATCH` 금지.

### AT-001-003 — Valid Authority Only

Authority ALLOW, required receipt 없음 → `READY_FOR_DISPATCH` 금지.

### AT-001-004 — Receipt + Authority

Valid receipt + ALLOW authority + gate CLEAR → `READY_FOR_DISPATCH`.

### AT-001-005 — Receipt Failure

Receipt rejected → `BLOCKED`, reason `TC-003_RECEIPT_REJECTED`.

### AT-001-006 — Authority Denial

Authority DENY → `BLOCKED`, reason `TC-004_AUTHORITY_DENIED`.

### AT-001-007 — Owner/Governance Hold

Receipt/authority가 모두 valid라도 protected gate `HOLD` → state `HOLD`, READY 금지.

### AT-001-008 — Invalid Transition

`SESSION_CREATED → DISPATCHED` 직접 전이 → reject/block.

### AT-001-009 — Idempotent Reapply

동일 receipt/authority result 재적용 → logical state 중복 전이 없음.

### AT-001-010 — Reference Mismatch

다른 session/trace에 속한 result 혼입 → `TC-006_REFERENCE_MISMATCH`.

### AT-001-011 — Dispatch Is Not Finish

`markDispatched()` 후 terminal evidence 없이는 `completeSession()` 실패.

### AT-001-012 — Terminal Evidence

DISPATCHED + valid terminal evidence refs → FINISHED.

### AT-001-013 — Determinism

동일 snapshot과 inputs에 대해 readiness decision 반복 결과 동일.

### AT-001-014 — Forbidden Dependencies

Trust Controller core dependency graph에 Provider/Portal/Runtime/Repository Write/Business Logic가 없어야 한다.

### AT-001-015 — Existing Trust Regression

Receipt/Provenance/Evidence/Trusted Merge 기존 regression PASS.
