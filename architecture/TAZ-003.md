## 1. Purpose

Authority Contract는 TAZ에서 **누가, 어떤 범위에서, 어떤 행위를, 어떤 조건으로 수행할 수 있는지**를 명시적으로 표현하고 검증하는 최소 권한 계약이다.

Authority Contract는 trust와 authority를 분리한다. Receipt가 검증되었다는 사실만으로 실행 권한이 생기지 않으며, 신뢰 가능한 actor라 하더라도 명시적 authority가 없으면 protected action은 허용되지 않는다.

핵심 원칙:

1. Default deny.
2. Least privilege.
3. Explicit scope.
4. Expiration/revocation 우선.
5. Delegation은 상위 권한을 확대할 수 없다.
6. Authority는 immutable/versioned reference로 감사 가능해야 한다.
7. 검증 실패·모호성·unknown version은 fail closed.

## 3. Requirements

### AC-001 — Default Deny

명시적으로 유효한 authority가 없거나 판단할 수 없는 경우 결과는 반드시 `DENY`다.

### AC-002 — Explicit Capability

Protected action은 authority의 `capabilities`에 명시적으로 포함되어야 한다. 역할명, provider 이름, trust state만으로 capability를 추론하지 않는다.

### AC-003 — Scope Match

Resource/subject/action scope가 요청과 일치해야 한다. wildcard는 contract에서 명시적으로 허용된 경우에만 사용한다.

### AC-004 — Least Privilege

Authority는 필요한 최소 capability와 scope만 표현한다. 하위 모듈이 편의를 위해 scope를 확대할 수 없다.

### AC-005 — Temporal Validity

`notBefore <= now < expiresAt` 조건을 만족해야 한다. 만료되었거나 아직 유효하지 않은 authority는 deny한다.

### AC-006 — Revocation Wins

revoked authority는 cache나 이전 allow decision보다 우선한다. revocation state를 확인할 수 없고 확인이 필수인 protected action은 fail closed 한다.

### AC-007 — Delegation Cannot Broaden

Delegated authority의 capabilities, scope, validity window, constraints는 parent authority의 부분집합이어야 한다.

### AC-008 — Deterministic Decision

동일 authority snapshot, request, evaluation time에 대해 동일 decision/reason을 생성해야 한다.

### AC-009 — Immutable Versioned Reference

사용된 authority snapshot은 `authorityId` + `version` 또는 이에 준하는 immutable reference로 추적 가능해야 한다.

### AC-010 — Auditable Denial

모든 allow/deny decision은 `traceId`, authority ref, matched capability/scope 또는 denial reason을 남긴다.

### AC-011 — Separation from Trust

`trusted`, `verified receipt`, `known provider` 상태만으로 authorization을 allow해서는 안 된다.

### AC-012 — Protected Gate Preservation

TAZ Authority Contract는 Program Owner의 Production/Public/G5, 법/보안 비가역 변경, 외부 지출 등 기존 explicit approval gate를 우회하거나 자동 승인하지 않는다.

```text

```

Public interface:

```typescript
export interface AuthorityEvaluator {
  evaluate(request: AuthorityEvaluationRequest): AuthorityDecision
}

export interface AuthorityEvaluationRequest {
  authority: AuthorityEnvelope
  principalId: string
  capability: string
  resource: ResourceDescriptor
  subject?: SubjectDescriptor
  context?: Readonly<Record<string, string | number | boolean>>
  evaluatedAt: string
  traceId: string
}

export type AuthorityDecision =
  | {
      decision: "ALLOW"
      authorityRef: string
      matchedCapability: string
      matchedScope: string
      traceId: string
    }
  | {
      decision: "DENY"
      authorityRef?: string
      reasonCode: AuthorityDenialCode
      traceId: string
    }
```

Evaluator는 side-effect free core를 기본으로 한다. Revocation source 조회 등 I/O는 boundary에서 snapshot을 공급하며, evaluator가 network/repository를 직접 호출하지 않는다.

## 5. Data Model

```typescript
export interface AuthorityEnvelope {
  schemaVersion: "1"
  authorityId: string
  version: string
  issuerId: string
  principalId: string
  capabilities: readonly CapabilityGrant[]
  resourceScope: readonly ScopeRule[]
  subjectScope?: readonly ScopeRule[]
  constraints?: readonly AuthorityConstraint[]
  issuedAt: string
  notBefore: string
  expiresAt: string
  revocation: RevocationSnapshot
  parentAuthorityRef?: string
  delegationDepth?: number
  evidenceRefs: readonly string[]
  traceRef?: string
}

export interface CapabilityGrant {
  capability: string
  scopeRefs: readonly string[]
}

export interface ScopeRule {
  scopeId: string
  type: string
  pattern: string
}

export interface AuthorityConstraint {
  key: string
  operator: "EQ" | "IN" | "LTE" | "GTE"
  value: string | number | boolean | readonly string[]
}

export interface RevocationSnapshot {
  state: "ACTIVE" | "REVOKED" | "UNKNOWN"
  checkedAt: string
  sourceRef?: string
}
```

### Authority Reference

권고 canonical reference:

```text
authorityRef = authorityId + "@" + version
```

version은 mutable alias가 아니라 immutable snapshot을 가리켜야 한다.

### Scope Semantics

- scope matching은 exact semantics가 기본이다.
- wildcard/glob/regex는 구현체가 임의 선택하지 않는다.
- pattern language가 필요하면 별도 versioned contract로 정의한다.
- 빈 scope는 `all`이 아니라 `none`으로 해석한다.

## 6. State Machine

Authority lifecycle 자체:

```text
ISSUED
  ↓ notBefore reached
ACTIVE
  ├──> EXPIRED
  └──> REVOKED
```

Evaluation flow:

```text
RECEIVED
  ↓ schema/version validation
VALIDATED
  ↓ principal match
PRINCIPAL_MATCHED
  ↓ temporal/revocation check
ACTIVE_CONFIRMED
  ↓ capability match
CAPABILITY_MATCHED
  ↓ resource/subject scope match
SCOPE_MATCHED
  ↓ constraints/delegation check
ALLOW
```

어느 단계에서든 실패:

```text
... → DENY
```

`ALLOW`와 `DENY`는 해당 evaluation에 대한 terminal result다. 이후 authority가 revoke되면 새 evaluation을 수행해야 하며 이전 allow를 영구 권한으로 재사용하지 않는다.

```typescript
  | "AC-004_CAPABILITY_NOT_GRANTED"

  | "AC-007_NOT_YET_VALID"
  | "AC-008_EXPIRED"
  | "AC-009_REVOKED"
  | "AC-010_REVOCATION_UNKNOWN"
  | "AC-011_CONSTRAINT_FAILED"
  | "AC-012_DELEGATION_INVALID"
  | "AC-013_SCOPE_AMBIGUOUS"
  | "AC-014_AUTHORITY_CORRUPT"
  | "AC-015_PROTECTED_GATE_REQUIRED"
```

Internal exception은 allow로 fallback하지 않는다. 정상적으로 decision을 만들 수 없으면 deny + safe diagnostic을 반환한다.

## 8. Security Requirements

1. Default deny를 코드·테스트 양쪽에서 강제한다.
2. Authority payload를 untrusted serialized input으로 취급하고 schema 검증 후 사용한다.
3. `principalId`, capability, scope를 string substring이나 느슨한 prefix 비교로 허용하지 않는다.
4. 만료/미래 authority는 deny한다.
5. revoked authority는 언제나 deny한다.
6. revocation이 필수인 action에서 `UNKNOWN`은 deny한다.
7. delegation chain은 cycle, depth overflow, parent missing, scope broadening을 reject한다.
8. child expiration은 parent expiration을 초과할 수 없다.
9. child capability/scope는 parent subset이어야 한다.
10. authority decision log에 credential, token, secret을 기록하지 않는다.
11. trust/receipt/provider metadata를 authority grant로 변환하지 않는다.
12. explicit Program Owner gate를 일반 capability로 우회하지 않는다.
13. evaluation은 current immutable authority snapshot에 bind한다.
14. cache 사용 시 authority version/revocation snapshot을 key에 포함한다.

## 9. Acceptance Tests

### AT-003-001 — Explicit Allow

유효 principal, capability, scope, time, constraints를 모두 만족하면 `ALLOW`.

### AT-003-002 — Missing Authority

Authority 없음 → `AC-001_MISSING_AUTHORITY`, `DENY`.

### AT-003-003 — Principal Mismatch

다른 principal의 authority 사용 → `DENY`.

### AT-003-004 — Capability Missing

scope가 맞아도 capability가 없으면 `DENY`.

### AT-003-005 — Resource Out of Scope

capability가 있어도 대상 resource가 scope 밖이면 `DENY`.

### AT-003-006 — Expired

`evaluatedAt >= expiresAt` → `AC-008_EXPIRED`.

### AT-003-007 — Not Yet Valid

`evaluatedAt < notBefore` → `AC-007_NOT_YET_VALID`.

### AT-003-008 — Revoked

Revocation state `REVOKED` → 항상 `DENY`.

### AT-003-009 — Delegation Broadening

Child가 parent에 없는 capability 또는 더 넓은 scope를 요청 → `AC-012_DELEGATION_INVALID`.

### AT-003-010 — Empty Scope

빈 scope는 all로 간주하지 않고 `DENY`.

### AT-003-011 — Unknown Version

알 수 없는 schema version → `DENY`.

### AT-003-012 — Determinism

동일 snapshot/request/time을 반복 평가하면 동일 decision/reason.

### AT-003-013 — Trust Is Not Authority

Trust Controller state가 READY이거나 receipt가 verified여도 authority grant가 없으면 `DENY`.

### AT-003-014 — Protected Owner Gate

Production/Public/G5 또는 별도 owner approval이 필요한 action은 일반 authority만으로 통과하지 않는다.

### AT-003-015 — Regression

기존 authorization/governance/receipt/evidence regression을 훼손하지 않는다.
