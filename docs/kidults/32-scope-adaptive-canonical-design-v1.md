# KIDULTS Adaptive Canonical 32-Scope Design v1

## Purpose
The 32 Collection Scopes are the current canonical market baseline, not a permanent category taxonomy. The system must remain stable enough to preserve identity, evidence, historical comparability and index lineage while adapting to changes in collectible markets and customer decisions.

## Canonical Architecture

```text
KIDULTS Semantic Core
  -> Global Collectibles Common Core
  -> 7 Market Archetypes
  -> 32 +/- N Versioned Collection Scopes
  -> Scope-specific Extensions
  -> Representative Products
  -> Market Cells
  -> Evidence Demand
  -> Source Demand
  -> Canonical / Evidence / Market Graph
  -> Cross-Scope Normalized Intelligence
  -> Portal / EOS / API / Reports
```

## Output-first Requirement Logic
Every Scope requirement must trace through:

```text
Customer Decision
-> Decision Failure
-> Irreplaceable Question
-> Irreplaceable Intelligence Output
-> Metric / Assertion
-> Evidence
-> Data
-> Source Role
-> Self-collected PoC
-> Gap Analysis
-> Provider Requirement (only if still required)
```

A data field without a customer-decision and evidence trace is not admitted merely because it is available.

## Three Speeds of Change
### Stable Core
KIDULTS / Collectibles definitions, canonical identity principles and evidence grammar should change slowly and only through explicit versioning.

### Adaptive Market Model
Market Archetypes, Collection Scopes and normalization models may evolve as sustained evidence shows market-structure change.

### Dynamic Market Layer
Representative Products, Market Cells, Dynamic Verticals, customer decisions, signals and source demand may change frequently.

## Scope is not Portal Category
A Canonical Collection Scope is an internal intelligence and evidence unit. A Portal Category is a customer experience construct. A Dynamic Vertical is an emerging market cluster. They may map to each other but must never be treated as identical.

## Dynamic Vertical Buffer
Emerging markets should normally enter as Dynamic Verticals rather than immediately creating new Scopes.

```text
Signal
-> Dynamic Vertical
-> Evidence accumulation
-> Scope Candidate
-> Independent Track B assessment
-> KPMO approval
-> New canonical Scope version
```

## Scope Admission Test
A new Scope requires all of the following: distinct customer decision, identity grammar, condition/provenance logic, market behavior, intelligence output, sufficient global market and persistent demand.

## Split / Merge / Archive
Scopes may split when one Scope contains materially divergent identity or market grammars. Scopes may merge when their decision, identity and market behavior converge. Declining scopes may be archived, but their historical observations and versions remain immutable.

## Scope Drift Monitoring
Scope Drift Score is composed of identity divergence (20%), market behavior divergence (20%), customer-decision divergence (20%), source-topology divergence (15%), condition/provenance divergence (15%) and regional divergence (10%).

- <30: STABLE
- 30-49: MONITOR
- 50-69: REVIEW
- >=70: SPLIT / NEW SCOPE CANDIDATE

The score creates a review recommendation, never an automatic canonical taxonomy mutation.

## Versioning and Historical Truth
Scope definitions are immutable once effective. Changes create a new scope version with effective dates, supersession link, reason and migration rule. Historical observations retain the Scope version under which they were originally observed; current interpretation may be mapped separately. Historical truth is never rewritten.

## Customer Need Evolution
A change in customer need should first modify the Decision Contract, not automatically the Scope. New data, metrics and outputs are then re-derived from the changed decision. Scope change is considered only if the underlying market grammar itself has materially diverged.

## Irreplaceable Value Revalidation
Every Scope output is periodically challenged against generic AI, marketplaces, single providers and open data. If an output becomes easily replaceable, KIDULTS must deepen or redesign it rather than preserve a legacy metric for continuity alone.

## North-Star Governance
Every Scope and Scope change must pass:
- AUTONOMOUS: sustainable refresh and change detection with bounded human intervention
- GLOBAL: explicit and testable geography/language/market bias model
- IRREPLACEABLE VALUE: decision value not sufficiently replicated by generic search, marketplace or one provider
- TRANSPARENT: provenance, evidence, confidence, limitations and version history visible to governed consumers

## Provider Boundary
Provider selection follows Scope requirements and self-collected PoC gap analysis. Providers must not define the Scope, Product Universe or required metrics. Provider authorization remains downstream of the canonical Scope requirement matrix.

## Desired End State
The moat is not the number 32. The moat is an Adaptive Canonical Scope System that continuously converts different global collectible markets into one defensible Intelligence Language without losing historical truth.
