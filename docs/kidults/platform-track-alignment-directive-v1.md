# KIDULTS Platform + Track A–E Alignment Directive v1

Status: CANONICAL CANDIDATE
Parent: #344 / #394
Canonical source baseline: main @ c4d981b4d6fbbc7eb057f7c2735f6525e5feb8cf
Production: HOLD

## 1. Purpose
This directive aligns the entire KIDULTS platform and Track A–E to the Adaptive Canonical Scope System. The current 32 Collection Scopes are a versioned baseline, not a permanent taxonomy.

## 2. Shared system of record
All Tracks SHALL consume the same semantic chain:
KIDULTS Market Lens → Collectibles Universe → Global Common Core → Market Archetype → Canonical Collection Scope → Representative Product → Market Cell → Assertion → Evidence → Source → Canonical/Evidence/Market Graph → Track B → Projection → Portal/EOS/API.

Canonical Scope != Portal Category != Dynamic Vertical.

## 3. Three speeds of change
- Stable core: KIDULTS/Collectibles definitions, canonical identity principles, evidence grammar.
- Adaptive model: archetypes, scopes, normalization models, versioned through governance.
- Dynamic layer: representative products, market cells, dynamic verticals, customer decisions, signals, source demand.

## 4. North-Star gate
Every Track output SHALL be evaluated against AUTONOMOUS, GLOBAL, IRREPLACEABLE_VALUE, and TRANSPARENT.

## 5. Track A — Intelligence / Evidence Factory
Owns: Scope-specific data requirement refinement, representative-product evidence demand, self-collected PoC, evidence admission, canonical identity/evidence/market graph build.
Must start from Decision → Irreplaceable Output → Assertion → Evidence → Data, never Source-first.
Must preserve NOT_VERIFIED and provider independence.
Does not approve its own rankability/publication.

## 6. Track B — Independent Validation
Owns: independent validation of Scope sufficiency, collectible qualification, representative-set bias, market-cell completeness, evidence sufficiency, source independence, scope drift recommendations, and index eligibility.
Official input remains immutable Track A candidate/evidence package only.
Must not consume Portal output as truth.
Scope create/split/merge/archive recommendations require independent validation before KPMO canonical versioning.

## 7. Track C — Portal / Customer Experience
Owns: customer-facing projection of canonical states, Dynamic Vertical UX, customer-decision signals, explanation of WHY/Evidence/Confidence/Limitation.
Portal may change categories/navigation faster than Canonical Scopes.
Portal shall never create canonical scope, qualification, metric, or market truth.
Customer behavior is a signal, not market truth.

## 8. Track D — Runtime / Reliability
Owns: versioned runtime for scope/product/cell/evidence workloads, DEV→STAGING→PRODUCTION separation, observability, recovery, cost, rollback, and audit.
Capacity shall be derived from Product × Market Cell × Evidence Demand × Refresh cadence, not fixed URL/source counts.
Production remains HOLD until G5.

## 9. Track E — IH Executive Operating System
Owns: projection of canonical lifecycle, scope drift, blockers, decisions, incidents, outcome status, and governance events.
EOS consumes registries/events; it does not create market truth.
Must expose Scope lifecycle and version transitions, including EMERGING/CANDIDATE/VALIDATED/CANONICAL/MATURE/DECLINING/MERGED/SPLIT/ARCHIVED.

## 10. Scope evolution governance
Signal → Dynamic Vertical → Evidence accumulation → Scope Candidate → Track B → KPMO → New Canonical Scope Version.
No autonomous direct promotion to canonical taxonomy.
Historical observations are never rewritten; reinterpretation is versioned.

## 11. Provider rule
External provider negotiation remains HOLD until:
1. 32/32 Scope Data Requirement contracts are refined,
2. representative self-collected PoCs exist,
3. exact field/evidence/geography/freshness gaps are quantified,
4. Provider Requirement Specification is frozen.
Providers are accelerators/gap-fillers/challengers, never business truth.

## 12. Shared fail-closed rules
No missing→zero.
No listing→sold.
No provider ID→canonical ID.
No UNKNOWN rights→PASS.
No source count→quality claim.
No Portal-side qualification/ranking.
No scope/category synonym assumption.
No history overwrite.
No production without G5.

## 13. Alignment acceptance
Alignment is complete only when Track A–E all reference this canonical model, preserve shared IDs/lifecycle states, and no downstream surface can bypass Scope/Data/Evidence governance.
