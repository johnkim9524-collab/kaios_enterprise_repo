# Provider External Correspondence Runbook

Before sending any provider message, the owner must check `registry/provider-registry.yaml`, prior email evidence, and the relevant vertical schedule.

The message must state the product hypothesis, minimum fields, permitted internal use, customer-facing output, retention/deletion, derivative/model rights, territory, support, pricing, and whether the message is only a rights-and-availability inquiry.

Never imply that a sent inquiry is a contract, approval, credential request, spend authorization, or integration commitment. Never resend the already-sent eBay Developer Relations inquiry unless a new follow-up is explicitly recorded.
