## Protected operational connection and cutover

The normal template remains code-only and has no new ledger authority. The separate `autonomous-event-token-broker-resume-v1.json` is an Owner-reserved bootstrap proposal. The existing no-authority-expansion validator remains unchanged; normal push cannot activate the new table/permissions. After authorized bootstrap, the normal deployer selects the retained RESUME template and preserves the activation floor with UsePreviousValue.

`ResumeActivationRunFloor` defaults to disabled (0). Set it to the latest actual repository Actions run ID at cutover; only later first attempts may dispatch. Land the new workflow on protected main before activation, so an old direct-transport workflow cannot send a new-main tuple outside the ledger. Never lower the floor or use a legacy generation as a canary.

A second tuple fence binds repository, PR, exact base/head/tree and scope, preventing a later natural clock from creating another dispatch for the same candidate. Unknown or in-flight records are never reclaimed or deleted. A legitimate recovery for an unchanged tuple needs a separately governed reconciliation adapter; no automatic retry is provided. A stored signature failure, including a key rotation without trusted old-key verification, stops reuse and does not permit another dispatch. Key rotation migration and ambiguous-outcome reconciliation remain acceptance requirements.

`DISPATCH_ACCEPTED` proves GitHub HTTP 204 acceptance only, not delivery to all roles, landing, finalizer consumption or whole-mission completion. The new receipt is authenticated in the protected ledger, not an S3 immutable terminal receipt. Original immutable terminal receipts remain unchanged.
