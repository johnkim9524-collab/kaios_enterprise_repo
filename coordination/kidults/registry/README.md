# KIDULTS AGCI-OS Registry v2.0

This directory is the canonical Registry foundation for the **Autonomous Global Collectibles Intelligence Operating System (AGCI-OS)**.

## First principle

```text
AUTONOMOUS
→ TRUST
→ EVIDENCE
→ MARKET STRUCTURE
→ INDEX
→ PROJECTION
→ DECISION
→ HOPE
```

## Canonical boundary

```text
Registry      Facts and governed state
Engine        Computation
Projection    Consumable product state
Experience    Portal / Executive / API / Reports
```

Portal and Executive consumers may read Projection contracts only. Direct Provider-to-Portal paths and intelligence calculations inside Portal components are prohibited.

## Record architecture

Each canonical Registry uses:

```text
<registry>/
├─ index.json
└─ records/
   └─ <immutable-record>.json
```

`index.json` contains versioned catalog pointers. Immutable record files contain business truth, contracts or governed outputs.

## Registry v2 business flow

```text
Autonomous Operating Contract
→ Global Collectibles Universe
→ Entity / Object Identity
→ Evidence + Market Events + Signals
→ Market Graph
→ Cluster Discovery
→ Dynamic Vertical Lifecycle
→ Vertical Intelligence Indexes
→ KIDULT 500
→ KIDULT 100
→ Projection Registry
→ Portal / Executive / API / Reports
```

## Compatibility rule

The previous eight `vertical-*` records remain unchanged for Candidate R1 and legacy consumers. They are now interpreted as **Core Domains v1**, an initial Provider-facing mapping interface. They are not permanent market Verticals and do not determine fixed KIDULT 500 or KIDULT 100 allocations.

## Non-negotiable rules

1. Stable IDs are never reused.
2. Published Candidate and Assessment records are never edited; corrections create new IDs.
3. Missing values remain missing and are never silently converted to zero.
4. Provider data enters Raw Quarantine and a Provider Mapping Contract before the Universe.
5. Market categories and Verticals are discovered, versioned outcomes of Evidence and Market Graph analysis.
6. Emerging Vertical promotion, public publication and Production remain human approval gates.
7. Raw Provider data never flows directly to Portal.
8. Production remains `HOLD` until all formal gates pass.
