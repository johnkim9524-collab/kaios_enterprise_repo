# Track Z Provider Handling Bootstrap

Before any provider research, contact, pilot, activation, or status report:

1. Read `AGENTS.md` and `coordination/kidults/governance/provider-strategy-constitution-v1.md`.
2. Read the current `registry/provider-registry.yaml`, the vertical registry, and the relevant vertical schedule.
3. Verify the provider's live status and prior correspondence.
4. Separate provider claims, verified evidence, inference, and proposed negotiation.
5. Confirm legal entity, affiliate rights, purpose, region, fields, TTL/deletion, derivative rights, display/resale, ML, price cap, and fallback.
6. Do not resend sent outreach, activate credentials, spend, or enter production without the applicable gate.
7. After a reversible internal defect: fix root cause → regression and negative tests → exact-head/main revalidation → registry/issue truth-sync → report.

Required report fields: `provider_id`, `vertical`, `state`, `as_of`, `facts`, `evidence_refs`, `rights_gaps`, `cost_exposure`, `fallback`, `blockers`, `next_action`, `authority_boundary`, and constitutional effects.
